Principe

Le Model Context Protocol (MCP) est un protocole par lequel un agent IA découvre puis appelle des outils externes. Ce serveur traduit l'API Magileads en outils MCP : l'agent interroge un compte, lance un ciblage ou audite une campagne sans connaître les détails de l'API — il voit des fonctions nommées, typées et documentées.

Les outils sont écrits en TypeScript, validés avec zod, et exécutés directement par Bun (aucune étape de compilation).

À retenir

L'agent ne reçoit jamais de clé d'API : il fournit des paramètres métier, le serveur exécute l'appel avec la clé du client et ne renvoie que le résultat.

Transports

Deux modes de connexion, selon que l'agent tourne en local ou à distance.

TransportPoint d'entréeÀ utiliser quand
stdio bun run src/index.ts L'agent lance le serveur comme sous-processus local (Claude Desktop / Code, Cursor, un script).
HTTP bun run src/http.ts L'agent se connecte par le réseau — agent distant ou conteneurisé. C'est le mode déployé.

Le transport HTTP est un endpoint MCP Streamable HTTP sans état : POST /mcp (réponse JSON), plus une sonde de vivacité non authentifiée GET /health. Chaque requête est indépendante — un serveur et un transport neufs sont créés puis fermés à chaque appel.

Authentification

Le transport HTTP est multi-tenant : chaque requête porte la clé d'API Magileads du client appelant, utilisée pour cette requête uniquement. Deux clients atteignent donc deux comptes différents. Il n'y a aucun jeton d'accès partagé à gérer, et le serveur ne stocke aucun secret par client.

MéthodeFormeRemarque
En-tête dédié X-Magileads-Api-Key: <clé> Recommandé.
En-tête standard Authorization: Bearer <clé> Pratique pour les fichiers de configuration.
Paramètre d'URL ?api_key=<clé> Pour les interfaces n'offrant qu'un champ URL. ?token= est aussi accepté.
Attention

Une clé passée dans l'URL peut apparaître dans les journaux d'accès du reverse-proxy. Préférer l'en-tête dès que le client le permet.

Une requête sans clé exploitable reçoit un 401, sauf si le serveur dispose d'un compte par défaut (voir Configuration), auquel cas elle retombe sur ce compte. La clé du client n'est jamais journalisée.

stdio

Le transport stdio est toujours mono-compte : il utilise les identifiants d'environnement, il n'y a pas de clé par requête.

Ciblage Google Maps

Le ciblage se fait en trois temps. L'ordre compte : chaque étape consomme la sortie de la précédente.

  1. generate_maps_search_urls

    À partir d'une activité et d'une ou plusieurs localisations, produit les URLs de recherche Google Maps.

  2. extract_maps_search

    Extrait les établissements depuis ces URLs et crée une nouvelle liste de contacts. L'extraction est asynchrone.

  3. get_contact_list_status

    Suit l'avancement des traitements jusqu'à la fin du remplissage de la liste.

Raccourci

run_google_maps_targeting enchaîne les étapes 1 et 2 en un seul appel — c'est l'outil à privilégier pour une demande du type « cible les dentistes à Lyon ».

Le ciblage consomme des crédits sur le compte Magileads et la génération d'URLs peut prendre plusieurs dizaines de secondes : prévoir des délais d'attente généreux côté client.

Garde-fous

Un agent IA peut se tromper. Les actions irréversibles sont donc supprimées ou verrouillées par le serveur, pas seulement déconseillées dans une consigne.

Aucune suppression de contacts

Le serveur n'expose aucun outil capable de supprimer des contacts, et le code correspondant a été retiré. Un agent ne peut donc pas vider une liste, même par erreur.

Écritures génériques

magileads_request est en simulation par défaut : il montre la requête qui serait envoyée et ne change rien. Il faut confirm: true pour exécuter réellement l'appel — et il n'accepte que POST, PUT et PATCH.

Surface restreinte

L'accès générique passe par une liste blanche d'endpoints non-admin. Les endpoints d'administration, de facturation, de revendeur et d'équipe sont exclus et ne sont pas appelables.

Filtres bornés

Une sélection est limitée à 30 critères, ce qui écarte les filtres dégénérés ou abusifs avant même l'appel à l'API.

Garantie

Aucune voie ne permet de supprimer quoi que ce soit : il n'existe pas d'outil de suppression, et la méthode DELETE est retirée de l'accès générique. La suppression reste possible pour un humain, depuis l'interface Magileads.

Accès API générique

Au-delà des outils dédiés, l'agent peut atteindre le reste de l'API Magileads. Le serveur embarque un index des endpoints appelables, généré depuis la spécification OpenAPI, filtré des routes d'administration et de toutes les routes DELETE — 45 endpoints ainsi écartés, que l'agent ne peut ni découvrir ni atteindre.

Lancer en local

Le serveur tourne sur Bun, qui exécute le TypeScript directement.

bun install

# stdio (agent local) — compte unique depuis l'environnement
MAGILEADS_API_KEY=... bun run start

# HTTP (multi-tenant) — les clients envoient leur propre clé,
# aucun identifiant serveur n'est nécessaire
bun run start:http

Vérifier l'endpoint HTTP

curl -s localhost:8080/health
# {"status":"ok"}

curl -s -X POST localhost:8080/mcp \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -H 'X-Magileads-Api-Key: VOTRE_CLE_MAGILEADS' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'

Déploiement

docker compose up -d --build

L'image est basée sur oven/bun, lance bun run src/http.ts, écoute sur le port 8080, s'exécute en utilisateur non-root et déclare un HEALTHCHECK sur /health.

Sur Dokploy

  • Créer une application depuis le dépôt et laisser Dokploy construire le Dockerfile.
  • Attribuer un domaine. Aucune variable d'environnement n'est requise en multi-tenant, puisque chaque client apporte sa clé.
  • Le reverse-proxy termine le TLS : les clients atteignent le serveur sur https://<domaine>/mcp.

Connecter un agent

Un agent compatible MCP découvre les outils automatiquement au démarrage. Deux façons de lui transmettre la clé du client.

Par fichier de configuration — recommandé

La clé reste dans la configuration du client et hors des URLs.

mcp_servers:
  magileads:
    url: "https://<domaine>/mcp"
    headers:
      X-Magileads-Api-Key: "<CLE_MAGILEADS_DU_CLIENT>"

Par URL

Pour les interfaces qui n'offrent qu'un champ URL, sans en-têtes personnalisés : transport HTTP, et https://<domaine>/mcp?api_key=<CLE>.

Isolation

La clé d'un client ne quitte jamais sa configuration. Le serveur ne détient aucun secret par client et route chaque requête vers le compte correspondant à la clé reçue.
